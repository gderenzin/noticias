Unpatched Tailscale SSH Flaws Could Let a Hacked Device Reach Root on Other Servers

Un informe de seguridad publicado recientemente detalla vulnerabilidades en la herramienta Tailscale SSH que permitirían a un dispositivo ya comprometido dentro de una red obtener acceso con privilegios de administrador (root) en otros servidores alcanzables. La investigación, basada en pruebas de laboratorio utilizando versiones específicas del software principal y de la variante autohospedada, señala que este tipo de ataque no requiere el uso de credenciales robadas, sino que se aprovecha de la configuración de reenvío de puertos y de las reglas de acceso establecidas. Las pruebas demostraron diferentes métodos para interactuar con sockets del sistema y sortear mecanismos de validación, logrando incluso la captura de secretos para incorporar equipos adicionales a la red, aunque este último paso se vio limitado en redes con ciertas funciones de seguridad activadas.

AI coding agents hijacked using AGENTS.md file in Downloads folder

Unos investigadores descubrieron un archivo de instrucciones malicioso llamado AGENTS.md en la carpeta de descargas de un usuario, el cual logró engañar a un asistente de programación de inteligencia artificial para que instalara un paquete npm no autorizado. El archivo en cuestión es de texto plano y suele utilizarse para guiar a los agentes en proyectos específicos, indicándoles herramientas o convenciones; sin embargo, al ser leído automáticamente desde el directorio de trabajo, puede provocar que el agente ejecute comandos o instale elementos basándose en los permisos con los que cuenta. Los especialistas reprodujeron esta clase de ataques empleando OpenAI Codex y Claude Code, demostrando que es posible filtrar credenciales y secuestrar cuentas mediante instrucciones maliciosas.

Los administradores del foro de Reddit dedicado al código abierto, r/opensource, prohibieron la publicación de cualquier iniciativa relacionada con la inteligencia artificial. OpenSSL 4.1.0: What’s new, what’s removed, and what’s still broken

El proyecto OpenSSL lanzó la versión 4.1.0, incorporando compatibilidad para la variante de transporte por datagramas DTLS 1.3, junto con cuatro fallos conocidos en su código DTLS. Dos de estos problemas pueden provocar que un programa interprete incorrectamente el estado de una conexión, haciendo que una falla permanente en la recepción se muestre como una solicitud de más datos o que un fallo de escritura reintentable se interprete de forma fatal. Otros inconvenientes señalados incluyen que un servidor DTLS 1.3 puede cancelar un proceso de negociación al recibir ciertos mensajes tras pérdidas de paquetes, y que el procesamiento de un mensaje KeyUpdate elimina otros registros posteriores de la memoria intermedia de retransmisión, lo que impide el reenvío de un tique de sesión si este se perdió inicialmente.
